# Architecture Decision Records

Use an ADR only for a durable, cross-cutting decision that future issues and maintainers must understand. Ordinary implementation detail, progress, and issue scope belong in the issue or pull request.

Name records sequentially:

```text
ADR-0001-short-decision-name.md
```

Each record should contain:

- status: proposed, accepted, superseded, or rejected;
- date and decision owners;
- context and forces;
- considered options;
- decision;
- consequences and compatibility/migration impact;
- links to the approving issue and pull request.

Supersede old decisions rather than rewriting their history.
